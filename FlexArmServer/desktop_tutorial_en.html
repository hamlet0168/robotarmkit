How to Make the Robot Recognize Your Desktop

This tutorial guides you through the full process of configuring desktop icon templates. Once done, the robotic arm can use template matching to identify desktop pages, auto-page to find target apps, and precisely tap icons to launch them.

ℹThe core of desktop recognition is template matching: the camera captures the phone screen, and OpenCV searches for regions that best match the icon templates. Recognition accuracy depends on the quality of template images.
1

Capture Desktop Screenshots

First, have the robotic arm capture the current phone desktop. Make sure the phone is positioned within the camera view and the screen is awake.

💡Take a screenshot via API POST /api/screenshot, or use the arm click to tap a blank area and wake the screen.

Below are example desktop screenshots from this tutorial (3 pages):

Page 0 — Weather, Settings, Video, Music, etc.
Page 1 — Quark, Qishui Music, Pydroid, etc.
Page 2 — WeChat, Alipay, TikTok, News, etc.

In each screenshot you can clearly see the various app icons. These icons are the templates we need to extract.

2

Crop Icon Templates

Crop each app icon from the screenshots and save as PNG files into the icons/ directory.

Cropping requirements
  • • PNG format, lowercase English name with underscores, e.g. app_qishui.png
  • • Complete icon body, with 2-3px padding around the edges (mask mode needs edge pixels for background sampling)
  • • No dynamic content (notification badges, countdowns, animations, etc.)
  • • Reasonable size, typically 60x60 ~ 120x120 pixels is enough
⚠When cropping, keep only the icon itself — do not include surrounding background color. Template matching uses the entire image to search the screen; background areas will interfere with matching.

3

Write the Desktop Configuration File

The desktop config file is at scripts/configs/app_desktop.yaml. It defines all recognizable desktop pages.

Configuration structure
FieldDescription
app_nameDesktop name (string, any name)
pagesList of pages, each with the following fields
namePage name, e.g. desktop_page0, desktop_page1
min_matchMinimum number of feature matches required to pass detection
must_featuresRequired features — all must match, otherwise the page is skipped
featuresOptional features — passes when match count ≥ min_match
typeFeature type: image (template matching) or text (OCR)
pathIcon template file path (used when type: image)
maskfalse = 4-corner background sampling (relaxed), true = strict template matching
Complete example
app_name: Phone Desktop

pages:
  # Page 1: Phone, Camera, Messages, Settings, Music
  - name: desktop_page0
    min_match: 2
    must_features:
      - name: Phone
        type: image
        path: icons/app_phone.png
        mask: false
      - name: Camera
        type: image
        path: icons/app_camera.png
        mask: false
    features:
      - name: Messages
        type: image
        path: icons/app_message.png
        mask: false
      - name: Settings
        type: image
        path: icons/app_settings.png
        mask: false
      - name: Music
        type: image
        path: icons/app_music.png
        mask: false

  # Page 2: Phone, Camera + more apps
  - name: desktop_page1
    min_match: 3
    must_features:
      - name: Phone
        type: image
        path: icons/app_phone.png
        mask: false
      - name: Camera
        type: image
        path: icons/app_camera.png
        mask: false
    features:
      - name: Qishui Music
        type: image
        path: icons/app_qishui.png
        mask: false
      - name: Quark
        type: image
        path: icons/app_quark.png
        mask: false

  # Task card page (multi-task switch view)
  - name: Task Card
    min_match: 0
    must_features:
      - name: Window Display
        type: image
        path: icons/task_show.png
        mask: false
      - name: Trash Bin
        type: image
        path: icons/task_delete.png
        mask: false
    features: []
💡must_features and features serve different purposes: must_features is the "gate" — all must pass before features are checked. Features form a "candidate pool" — the page is identified when enough features match (min_match).
4

Detection Principle

When the program runs detect_desktop, it works as follows:

Detection flow

Step 1: Camera captures the current phone screen (rotated 90° for portrait mode)

Step 2: Iterate through every page defined in the config (page0 → page1 → page2 → Task Card)

Step 3: For each page, check must_features first (all must match). If any fails, skip that page

Step 4: Once required features pass, check features and count matches

Step 5: When match count ≥ min_match, the current screen is identified as that page

Template matching

OpenCV uses cv2.matchTemplate() to search the screen for regions most similar to the icon template. It returns the highest similarity score and its position. Default threshold is 0.75 — scores above this are considered a match.

ℹWith mask: false, the program samples colors at the 4 corners of the template as background, ignoring those pixels during matching. This tolerates small variations in icon size/position. Desktop icons should generally use mask: false.
5

Page Navigation

Once desktop is configured, the robotic arm can auto-navigate between pages using these APIs:

APIMethodDescription
POST /api/go_homePOSTReturn to desktop: checks if on desktop, if not swipes up repeatedly until desktop is detected
POST /api/go_forwardPOSTPage forward (swipe left gesture), switch from current page to the next
POST /api/go_backPOSTPage backward (swipe right gesture), switch from current page to the previous
POST /api/run_appGET/POSTSmart app launch: go_home → detect page → auto-page to target → tap icon
run_app auto-page flow

Execution flow for POST /api/run_app {"app_name": "Qishui Music"}:

1. go_home ensures we are on the desktop

2. Detect current page and determine distance to target page

3. Auto-execute go_forward or go_back until the target page is reached

4. Use template matching on the target page to find and tap the icon

5. Safety limits: max 20 loop iterations, 3 tap attempts

⚠Page ordering depends on the numeric order of page names in app_desktop.yaml. Name pages as desktop_page0, desktop_page1, desktop_page2, etc. — the program auto-sorts by number.
6

Test & Verify

After configuration, verify desktop recognition works with these APIs:

Detect current desktop page
# Detect current page, returns page name and confidence
POST /api/detect_desktop
# Response: {"ok":true,"data":{"page_name":"desktop_page1","score":0.94,"matched":true}}
Launch an app
# Have the arm auto-find and tap the "Qishui Music" icon
POST /api/run_app {"app_name": "Qishui Music"}
# Response: {"ok":true,"data":{"launched":true}}
Find a specific icon
# Search for "Quark" icon in current frame
POST /api/find_template {"path": "icons/app_quark.png", "threshold": 0.75}
# Response: {"ok":true,"data":{"x":242,"y":516,"w":55,"h":55,"score":0.92}}
💡If an icon can't be found, try: 1) Lower threshold to 0.65; 2) Set mask: false; 3) Specify an roi to narrow the search area; 4) Check if the template image actually matches the icon on screen.
